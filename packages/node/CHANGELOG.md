## 2.5.1

### Patch Changes

- 5524e7e: proveWithWasm now passes `{ keccakZK: true }` to bb.js.

  Without it bb.js picks its default proof flavour, whose byte layout no
  `bb write_solidity_verifier` contract accepts — the length gate rejects it,
  so every browser-generated proof reverted on-chain (surfacing as wallets
  falling back to absurd gas limits after a failed estimation). CLI-generated
  proofs were unaffected. Both the node wasm path and the browser entry share
  this backend, so one change covers them.

  - @invisi-labs/core@2.5.1

## 2.5.0

### Minor Changes

- b4f7f5b: Move the proving backend to barretenberg 4.2.0 (stable).

  The previous pin, `@aztec/bb.js@4.0.0-nightly.20260120`, matched the on-chain
  verifiers generated by the same nightly. That nightly no longer exists in any
  package ecosystem, which left the Rust mobile prover unable to ever match the
  deployed verifiers. The whole toolchain (bb CLI for verifier generation,
  bb.js for web proving, barretenberg-rs for native proving) is now anchored at
  the stable 4.2.0 release.

  Proof format changes with this: proofs are 8 field elements shorter. SDKs at
  this version only verify against contracts whose verifiers were regenerated
  with bb 4.2.0 — pair the upgrade with the matching deployment.
